Low-bandwidth AI triage

Text-based symptom routing that is explicit about its limits.

The checker is designed for low data use and routes queries to self-care guidance, clinic review, urgent referral, or clinician follow-up.

Ganiley Triage Assistant Text-only
Describe the main symptom, age, duration, and any danger signs. I can help route the query, but I do not replace clinicians.
Examples: “child fever 2 days vomiting”, “pregnant severe headache”, “diarrhoea blood in stool”.

Routing principles

Emergency signs: difficulty breathing, unconsciousness, seizures, severe dehydration, heavy bleeding, chest pain, pregnancy danger signs, infant fever.
This tool provides triage routing and question prompts. It is not a diagnosis and does not replace a clinician.
Low data pattern: short text prompts, saved conversations, SMS-style alerts, and clinician escalation when online.

Unified delivery architecture

Website, app, backend sync, maps, AI triage, and admin protocol updates.

Production design assumes 2G/3G, intermittent power, low-end devices, compressed assets, and local-first data.

1. Offline app core

SQLite/local storage for diaries, protocols, facility lists, cached map tiles, and pending sync actions.

2. Unified backend

Conflict-aware sync API for diary exports, protocol versions, reminders, analytics, and facility updates.

3. Admin panel

Clinical editors update protocols, set version numbers, mark urgent changes, and push cache updates.

4. Lightweight triage

Text-first symptom checker with rule-based safety routing and optional clinician escalation.

5. Cached maps

OSM/Google integration online; offline tile bundles and facility coordinates for rural areas.

6. Cross-country learning

Comparisons frame transferable operations, not rankings. SSA ↔ SSA and SSA ↔ Nordic supported.
